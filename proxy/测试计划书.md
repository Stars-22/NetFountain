# 代理层（接口 IP 池）测试计划书

## 1. 测试目标与范围

验证代理层**路由表加载与热更新、按站点透传分发、健康检查**的正确性、并发安全性与鲁棒性。代理层为纯透传网关，测试重点是路由正确性与故障隔离。

**范围**：`app/` 下 `registry.py`、`dispatcher.py`、`routes.py`、`stats.py`。
**不在范围**：IP 拉取/测试/租赁逻辑（一级池、二级池）。

## 2. 测试环境与工具

| 项 | 说明 |
|---|---|
| Python | 3.14 |
| 测试框架 | pytest + pytest-asyncio |
| 网络桩 | aioresponses + 本地 mock 二级池服务 |
| 覆盖率 | pytest-cov |
| 依赖文件 | `requirements-dev.txt`：`pytest, pytest-asyncio, pytest-cov, aioresponses` |

## 3. 测试层级

| 层级 | 说明 |
|---|---|
| 单元测试 | registry/dispatcher 纯逻辑，网络打桩 |
| 集成测试 | mock 二级池 → 用户经代理访问闭环 |
| 端到端 | 代理层 + 二级池 + 一级池 + mock 供应商全链路 |
| 性能测试 | 高并发透传 |
| 鲁棒性测试 | 重载失败、单站点故障、上游超时 |

## 7. 测试桩与 Fixture 设计

- mock 二级池：本地 FastAPI 服务，实现 status/count/ips/acquire/release/delete/release-all，返回固定 `{code,msg,data}`，可配置故障/延迟。
- `conftest.py`：
  - `event_loop`、`mock_session`（aioresponses）
  - `registry`：预置多站点路由表的 Registry fixture
  - `dispatcher`：指向 mock 二级池的 Dispatcher fixture
  - `tmp_routes`：临时路由配置文件 fixture
- 桩对象：二级池正常响应 / ConnectionError / TimeoutError / 非法配置。

## 9. 执行方式

```bash
pip install -r requirements-dev.txt

# 单元 + 集成
pytest -v --cov=app --cov-report=term-missing

# 仅 registry
pytest tests/test_registry.py -v

# 仅 dispatcher
pytest tests/test_dispatcher.py -v

# 集成
pytest tests/test_integration.py -v

# 性能
pytest tests/test_perf.py -v -m perf
```

## 10. 缺陷管理与退出准则

- **缺陷分级**：P0（阻断）必须修复复测；P1（重要）需修复；P2 可排期。
- **退出准则**：P0/P1 清零；registry/dispatcher/routes/stats 覆盖率 ≥ 95%；全部用例通过后方可发布。
- 代理层改动需回归与二级池的透传契约（路径剥离、`{code,msg,data}` 原样返回）。
