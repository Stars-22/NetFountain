# 代理层（接口 IP 池）项目策划书

## 1. 项目概述

代理层是面向所有用户的**统一入口**。所有用户通过它访问所有二级池，无需知道每个二级池的地址。请求时在路径中附带站点标识，代理层据此路由到对应的二级池服务。

- 路由：站点标识 → 二级池 host:port（来自配置文件）
- 配置热更新：每分钟自动重载配置文件
- 语义：纯透传代理，不缓存 IP、不参与租赁逻辑
- 健康检查 `/health`：返回代理层自身统计 + 实时聚合一级池/各二级池 `/status`

## 2. 项目定位与边界

**只做**：按站点路由、透传请求/响应、每分钟重载路由表、健康检查（自身统计 + 实时聚合一二级池 `/status`）。
**不做**：任何 IP 拉取/测试/租赁逻辑——全部透传给二级池；也不统计任何二级池业务信息（如上游业务码）。

**对外依赖**：二级池 HTTP API（网络）；`ip_pool_common`（公共库）。
**被依赖**：所有用户（通过本服务统一访问二级池）。

## 3. 技术选型与依赖

| 类别 | 选型 |
|---|---|
| Web 框架 | FastAPI + uvicorn |
| 并发模型 | asyncio（单事件循环） |
| HTTP 客户端 | aiohttp（透传转发） |
| 配置 | pydantic-settings + PyYAML |
| 公共库 | ip_pool_common |
| 测试 | pytest + pytest-asyncio + aioresponses |

## 6. 数据模型

```python
@dataclass
class SiteRoute:
    name: str                 # 站点标识(路径键)
    base_url: str             # 二级池服务地址，如 http://127.0.0.1:8001
    # 可选元信息(供 health/调试展示)
    target_url: str | None = None
```

## 7. 核心模块设计

### 7.1 registry.py —— 路由表（热更新）

```python
class Registry:
    def __init__(self, route_file: str | None = None, route_url: str | None = None): ...
    async def load(self) -> int:
        # 从本地文件或 URL 读取 yaml/json → {site: SiteRoute}；校验合法后原子替换
    async def reload_loop(self):      # 每 reload_interval(60s) 调用 load()
    def get(self, site: str) -> SiteRoute | None
    def sites(self) -> list[SiteRoute]
```

**关键点**：
- 支持本地文件与远程 URL 两种来源（`route_file` / `route_url` 二选一或并存）。
- 重载采用「读新 → 校验 → 原子替换」策略，加载失败保留旧表，不影响在线服务。
- 配置文件格式：

```yaml
sites:
  - name: site_a
    base_url: http://127.0.0.1:8001
    target_url: https://www.example.com
  - name: site_b
    base_url: http://127.0.0.1:8002
    target_url: https://www.example.org
```

### 7.2 dispatcher.py —— 透传分发

```python
class Dispatcher:
    def __init__(self, registry: Registry, session: aiohttp.ClientSession): ...
    async def forward(self, site, method, path, params=None, json=None, timeout=10.0):
        # 1. route = registry.get(site)；不存在 → 站点未配置错误
        # 2. 转发到 f"{route.base_url}{path}"，透传 method/query/body
        # 3. 原样返回二级池的 status + json(统一响应透传)
```

**关键点**：
- 纯透传：不解析业务字段，`{code,msg,data}` 原样返回，保证一致性。
- 路径转换：`/api/v1/{site}/ips/acquire` → 转发至 `{base_url}/api/v1/ips/acquire`（剥离 site 段）。
- 二级池不可达/超时 → 返回统一网关错误码，不阻断其它站点。

### 7.3 routes.py —— 路由

见第 9 节。站点参数通过路径捕获后交给 `Dispatcher.forward`。

## 8. 核心流程

```
启动 → 创建 Registry + Dispatcher + session → 首次 load() → 启动 reload_loop
请求到达: 解析 {site} → registry.get(site) → 命中则透传 → 未命中返回错误
reload_loop 每60s: 重载路由表(失败保留旧表)
关闭: 取消重载任务 → 关闭 session → 优雅退出
```

## 9. API 设计

基路径 `/api/v1`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 健康检查 + 已配置站点列表 + 实时聚合一级/二级池 `/status` |
| GET | `/{site}/status` | 透传二级池 |
| GET | `/{site}/count` | 透传二级池 |
| GET | `/{site}/ips` | 透传二级池 |
| POST | `/{site}/ips/acquire` | 透传二级池 |
| POST | `/{site}/ips/{id}/release` | 透传二级池 |
| DELETE | `/{site}/ips/{id}` | 透传二级池 |
| POST | `/{site}/ips/release-all` | 透传二级池 |

透传端点统一返回二级池的原始 `{code,msg,data}`；站点未配置返回 `{code: 40400, msg:"site not configured"}`。

## 10. 配置设计（config/proxy_routes.yaml 与 ProxySettings）

```yaml
service:
  host: 0.0.0.0
  port: 9000
  log_level: INFO

registry:
  route_file: config/proxy_routes.yaml   # 本地路由文件(或 route_url 远程)
  route_url: ""                           # 可选：远程配置地址
  reload_interval: 60.0                   # 重载周期

level1:
  base_url: http://127.0.0.1:8000        # 一级池地址(供 /health 聚合一级池 /status)
  timeout: 5.0                           # /health 聚合一级池状态超时

dispatch:
  timeout: 10.0                           # 转发超时
```

## 11. 鲁棒性与容错

- **热更新安全**：重载失败保留旧表，服务不中断。
- **站点隔离**：单站点不可达仅该站点报错，不影响其它站点与整体可用性。
- **转发超时**：统一超时，避免悬挂请求拖垮上游。
- **未知站点**：返回明确错误码，不抛 500。
- **优雅启停**：`lifespan` 统一管理重载任务与连接。

## 12. 可扩展性

- 配置源可扩展：本地文件 / 远程 URL 已支持，未来可加数据库/服务发现。
- 路由表即插即用：新增站点只需在配置中加一行，无需改码或重启（每分钟生效）。
- 转发策略可扩展：未来可加负载均衡、限流、鉴权（透传层加入，不影响二级池）。

## 13. 测试策略

- `test_registry.py`：文件/URL 加载、非法配置报错、重载原子替换、get/sites 正确。
- `test_dispatcher.py`：路径剥离、method/query/body 透传、站点未配置错误、上游不可达/超时错误码。
