# 一级 IP 池（主 IP 池）项目策划书

## 1. 项目概述

一级池（主 IP 池）是整个代理 IP 体系的上游数据源。它**只负责从公网 IP 池（供应商）拉取 IP 并做「代理侧」连通性测试**，测试通过者放入内存环形池对外提供。它不关心具体站点，不关心使用者是谁。

- 拉取节奏：每 1 秒拉取 10 个（受供应商限频，严格限频）
- 入池测试：仅验证「能否连接代理」（`proxy_reachability_test`），**不测出口**
- 池容量：上限 500，循环队列淘汰最旧；供应商支持 TTL 时按时间淘汰
- 对外：HTTP API（供二级池增量同步）

## 2. 项目定位与边界

**只做**：拉取 → 代理可达性测试 → 入池 → 淘汰 → 对外查询 API。
**不做**：站点级测试、租赁管理、用户侧代理——这些分属二级池与代理层。

**对外依赖**：供应商公网 IP 池 API（网络）；`ip_pool_common`（公共库）。
**被依赖**：二级池通过本服务 HTTP API 增量同步（进程级解耦，非代码依赖）。

## 3. 技术选型与依赖

| 类别 | 选型 |
|---|---|
| Web 框架 | FastAPI + uvicorn |
| 并发模型 | asyncio（单事件循环，锁 + 信号量） |

## 7. 核心模块设计

### 7.1 providers/ —— 供应商客户端（注册工厂 + 模板方法，高扩展性）

> 层级：`providers/base.py`（基类 + 工厂 + 共享解析工具）+ 四个实现各自独立文件（`default_http.py` / `http91.py` / `freeproxy.py` / `juliangip.py`），`providers/__init__.py` 统一导入完成注册。

```python
class BaseProvider(ABC):
    name: ClassVar[str]
    def __init__(self, cfg: dict, session: aiohttp.ClientSession): ...

    async def pull(self, count: int) -> list[ProviderIp]:
        """模板方法：构建参数 → GET 请求 → 解析响应。
        网络/超时/HTTP/解析异常统一记日志后原样抛出；CancelledError 不拦截。"""

    @abstractmethod
    def _params(self, count: int) -> dict[str, str]: ...   # 构造查询参数

    @abstractmethod
    def _parse(self, payload, count) -> list[ProviderIp]: ...  # 解析响应体

    async def close(self): ...

# 示例：默认 HTTP 供应商
@register("default_http")
class DefaultHttpProvider(BaseProvider):
    def _parse(self, payload, count):
        # GET api_url(count, api_key) → 解析 {data:[{ip,port,protocol,region,ttl}]}
        ...

# 91HTTP 供应商（真实商用）：
@register("http91")
class Http91Provider(BaseProvider):
    # GET api_url(trade_no, secret, num, format=json, time=1, protocol)
    # 解析 {code,data:{proxy_list:[{ip,port,expire_time}]}}
    # expire_time 绝对时间 → 剩余秒数写入 ProviderIp.ttl
    # protocol: 1=HTTP, 2=SOCKS5

# 巨量IP 供应商（不限量代理）：
@register("juliangip")
class JuliangipProvider(BaseProvider):
    # GET api_url(trade_no, num, pt, result_type=json, ip_remain=1, sign)
    # sign = MD5(参数按名升序拼接 + &key=<api_key>)
    # 解析 {code:200,data:{proxy_list:["ip:port,剩余秒数"]}}
    # ip_remain 后缀 → 剩余秒数写入 ProviderIp.ttl
    # pt: 1=HTTP, 2=SOCK

# 扩展：新增供应商 = 新建文件实现两个钩子并注册，__init__.py 导入
@register("supplier_x")
class SupplierXProvider(BaseProvider):
    ...

class ProviderFactory:                                  # base.py
    _registry: dict[str, type[BaseProvider]] = {}
    @classmethod
    def register(cls, name, provider_cls): ...
    @classmethod
    def create(cls, provider_type: str, cfg: dict, session) -> BaseProvider:
        # 按 config.provider.type 实例化；未知类型抛明确异常
```

**扩展性（开闭原则）**：新增供应商只需「新建文件 + 继承 `BaseProvider` 实现 `_params`/`_parse` 两个钩子 + `@register("名字")`」，HTTP 请求/超时/异常包装由基类模板方法统一处理，主流程（拉取/测试/入池）零改动。共享解析工具（`parse_host_port`/`parse_optional_float`/`payload_dict`/`items_list`/`coerce_protocol`）收敛在 base.py。

### 7.2 core/pool.py —— 环形池（循环队列 + TTL + 协议计数）

```python
class Level1Pool:
    def __init__(self, max_size: int = 500):
        self._records: dict[int, IpRecord] = {}       # id → 记录
        self._order: deque[int] = deque(maxlen=max_size)  # 循环队列，满则弹出最旧
        self._counts: dict[Protocol, int] = Counter()
        self._key_index: dict[str, int] = {}          # proxy_url → id（去重索引）
        self._duplicates: int = 0                     # 重复拉取被跳过（region 未变且 ttl 未延长，或新拉取无 ttl）的累计次数
        self._next_id: int = 0
        self._lock = asyncio.Lock()

    async def add(self, ip: ProviderIp, now: float) -> IpRecord:
        # 按 proxy_url(ip+port+protocol) 去重：region 未变且 ttl 未延长（新<=旧，
        #   含双方均无 ttl）或新拉取无 ttl（不覆盖有限 ttl）时直接跳过不更新，
        #   duplicates 只累计跳过；其余重复删除旧记录并分配新 id 重建
        #   （刷新 ttl/region，移至队尾，新 id 触发二级池增量同步）（重建不计入）
        # 新记录分配自增id → 入 dict → 入 deque(maxlen 满自动丢弃最旧并同步计数) → 计数+1
    async def sweep_ttl(self, now: float) -> int:
        # 遍历按 created_at+ttl 删除过期项，返回删除数（供应商支持TTL时生效）
    def size(self) -> int
    def counts(self) -> PoolCounts
    @property
    def max_id(self) -> int | None                 # 当前池内最大 id（池空 None），O(1)
    @property
    def duplicates(self) -> int                    # 重复拉取被跳过更新（ttl 未延长/新无ttl）的累计次数
    async def all(self) -> list[IpRecord]                       # 按入池顺序
    async def after(self, id_: int) -> list[IpRecord]           # id > id_ 的全部
```

**关键点**：
- 容量淘汰由 `deque(maxlen=500)` 天然实现，O(1)；TTL 淘汰为周期性清扫，二者独立，TTL 优先于容量兜底。
- 以 `proxy_url`（ip+port+protocol）为去重键：region 未变且 ttl 未延长（新 ≤ 旧，含双方均无 ttl）时**直接跳过不更新**（零副作用、不推进水位线）；新拉取无 ttl 但池内有 ttl 时同样**跳过**（无论 region 是否变化，避免有限 ttl 被覆盖为永久，旧记录等 TTL 清扫移除后下次拉取重新入池）；其余重复（region 变化、ttl 延长续期、永久升级为有限）**删除旧记录、分配新 id 重建**（刷新 ttl/region、记录移至尾部），新 id 作为增量同步水位线的推进依据保证二级池能感知刷新。`duplicates` 只累计跳过次数，随 `/status` 暴露（`total_duplicates`）。
- 所有变更在 `asyncio.Lock` 下进行，保证并发安全。
- `id` 全局自增、绝不复用，作为二级池增量同步的水位线依据。

### 7.4 tasks/ —— 后台任务（拉取与测试解耦 + 多 worker 测试管线）

> 组合 `ip_pool_common.concurrency` 的通用设施：`TickLoop`（tick 起点计时节奏）+ `BoundedTestPipeline`（有界队列 + worker 池 + drop-oldest）+ `resolve_worker_count`，本层只保留业务语义（统计落点、供应商明细）。

```python
class PullTask:                                          # tasks/pull.py
    async def run(self):
        # 由 BoundedTestPipeline.run_supervised 驱动 TickLoop：
        while not cancelled:
            start = time.monotonic()
            async with self._pull_lock:                    # 只保护拉取（供应商限频点）
                raw = await self.provider.pull(cfg.pull_count)
                self.stats.total_pulled += len(raw)
                if raw: self._pipeline.enqueue(raw)        # 入有界队列(buffer)，不等测试
            await asyncio.sleep(max(0, pull_interval - (now-start)))  # 按 tick 起点计时保 1s 节奏
    async def _process_batch(self, raw):                   # 管线 worker 回调：测试并提交
        passed = await self._tester.test_many(raw)         # 每批内部按 test_concurrency 并发
        for ip in passed: await self._pool.add(ip, time())
        self.stats.total_entered += len(passed)
    # 队满时丢最旧待测批次并累计 drops/stats.drops（有界内存），
    # 被丢弃的 IP 仍计入 total_pulled（on_drop 回调）

class TtlSweeper:                                        # tasks/ttl.py
    async def run(self):                                    # 复用 run_periodic，每 cfg.ttl_sweep_interval(默认5s)
        removed = await self.pool.sweep_ttl(time())
```

**鲁棒性**：拉取/测试任何异常仅记录日志，不中断循环；下次 tick 自动重试。拉取与测试解耦后，测试耗时不拖慢 1s 拉取节奏；队列有界，供应商突发快拉时不会撑爆内存（丢最旧批次兜底）。

### 7.5 api/ —— 路由与序列化

见第 9 节。`api/routes.py` 定义 4 个端点，`api/serializers.py` 负责 `IpRecord → dict` 响应契约；统一响应 `{code, msg, data}`，API 调用计数由 `ApiCounterMiddleware`（path_prefix/counter 注入）累计，业务码日志由 `BizCodeLogMiddleware` 记录。

## 8. 核心流程

```
启动(lifespan) → 创建 ProviderFactory 实例 + Level1Pool + 启动 PullTask/TtlSweeper
PullTask: 每1s 拉取(锁内) → 批次入队 → 多 worker 并发代理可达性测试(纯握手) → 通过者入池(proxy_url 去重) → 统计累加
TtlSweeper: 每5s 清扫 TTL 过期项(若供应商支持TTL)
API 查询: 直接读内存池快照(加锁)；/status 含 total_duplicates
关闭: 取消后台任务 → 关闭 provider/session → 优雅退出
```

## 11. 鲁棒性与容错

- **限频保证**：`pull_lock` 只保护拉取（供应商限频点），固定按 tick 起点计时 `sleep(pull_interval)`，测试耗时不再拖慢拉取节奏。
- **异常隔离**：供应商故障/网络抖动只影响当前 tick，循环不中断；连续失败记 WARN 日志；单个测试批次异常仅记日志并累计 `test_failures`。
- **内存有界**：待测批次用有界队列（`test_buffer`），队满丢最旧批次（`drops` 累计），环形池固定上限，无内存膨胀风险。
- **超时控制**：拉取、测试均设 aiohttp 超时，避免悬挂。
- **去重刷新与跳过**：按 `proxy_url` 去重，region 未变且 ttl 未延长（新 ≤ 旧，含双方均无 ttl）或新拉取无 ttl（不覆盖有限 ttl）时直接跳过不更新；其余重复入池删除重建（刷新 ttl/region、新 id），`duplicates` 只累计跳过次数并随 `/status`（`total_duplicates`）暴露。
- **default_ttl 默认过期**：供应商未返回 ttl 的 IP 在拉取后填充条目配置的 `default_ttl`（秒），到期由 TTL 清扫移除、下次拉取重新入池；未配置则视为永久。
- **优雅启停**：`lifespan` 统一启停任务；收到退出信号取消任务、关闭连接。
- **空池/边界**：池空时 `all/after` 返回空数组；`after` 的 id 越界返回空数组。`/ips/after/{id}` 响应顶层携带 `max_id`（当前池内最大 id，池空为 null）：二级池在增量空响应时，仅当水位线大于 `max_id`（一级池重启/换代）才触发全量重拉，等于 `max_id` 视为暂无新 IP 不重拉。

## 12. 可扩展性

- 供应商：继承 `BaseProvider` + 工厂注册，新增供应商零侵入主流程。
- 测试原语：`tester` 依赖注入测试函数，可替换为其它验证策略。
- 淘汰策略：容量淘汰与 TTL 淘汰解耦，未来可加「质量评分淘汰」等。
- 参数：全部阈值/周期配置化，无需改码。
