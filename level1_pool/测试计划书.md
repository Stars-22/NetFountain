# 一级 IP 池（主 IP 池）测试计划书

## 1. 测试目标与范围

验证一级池**拉取、代理可达性测试、环形池管理、TTL 淘汰、统计与对外 API** 的正确性、并发安全性与鲁棒性。

**范围**：`app/` 下 `provider.py`、`pool.py`、`tester.py`、`tasks.py`、`routes.py`。
**不在范围**：供应商真实服务（用 `tests/mock_provider.py` 桩替代）、二级池/代理层。

## 2. 测试环境与工具

| 项 | 说明 |
|---|---|
| Python | 3.14 |
| 测试框架 | pytest + pytest-asyncio |
| 网络桩 | aioresponses + 本地 `mock_provider.py`（FastAPI 模拟供应商） |
| 覆盖率 | pytest-cov |
| 依赖文件 | `requirements-dev.txt`：`pytest, pytest-asyncio, pytest-cov, aioresponses` |

## 3. 测试层级

| 层级 | 说明 |
|---|---|
| 单元测试 | pool/provider/tester/tasks 纯逻辑，网络打桩 |
| 集成测试 | mock 供应商 → 拉取 → 测试 → 入池 → API 闭环 |
| 端到端 | 与二级池联调（跨项目，见二级池测试计划书） |
| 性能测试 | 拉取吞吐、池查询延迟、内存稳定性 |
| 鲁棒性测试 | 供应商故障、超时、高并发竞态 |

## 7. 测试桩与 Fixture 设计

- `tests/mock_provider.py`：本地 FastAPI 服务，模拟供应商接口，可配置返回数量/协议/失败率/延迟，供集成与性能测试。
- `conftest.py`：
  - `event_loop`、`mock_session`（aioresponses）

  - `pool`：预置多协议记录的 Level1Pool fixture
- 桩对象：供应商正常响应 / 空响应 / 畸形响应 / 超时 / 500。

## 9. 执行方式

```bash
pip install -r requirements-dev.txt

# 单元 + 集成
pytest -v --cov=app --cov-report=term-missing

# 仅 pool
pytest tests/test_pool.py -v

# 集成（需先起 mock_provider）
pytest tests/test_integration.py -v

# 性能
pytest tests/test_perf.py -v -m perf
```

## 10. 缺陷管理与退出准则

- **缺陷分级**：P0（阻断）必须修复复测；P1（重要）需修复；P2 可排期。
- **退出准则**：P0/P1 清零；pool/provider/routes 覆盖率 ≥ 95%；全部用例通过后方可发布。
- 一级池改动需回归二级池同步相关用例（跨项目契约）。
