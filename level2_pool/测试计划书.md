# 二级 IP 池（子 IP 池 / 站点级）测试计划书

## 1. 测试目标与范围

验证二级池**增量同步（含空响应 max_id 判定）、站点连通测试、租赁分配/释放/删除、周期复验、TTL 淘汰与对外 API** 的正确性、并发安全性与鲁棒性。租赁语义与并发分配是测试重点。

**范围**：`app/` 下 `syncer.py`、`pool.py`、`tester.py`、`tasks.py`、`routes.py`。
**不在范围**：供应商拉取（一级池）、代理层路由。

## 2. 测试环境与工具

| 项 | 说明 |
|---|---|
| Python | 3.14 |
| 测试框架 | pytest + pytest-asyncio |
| 网络桩 | aioresponses（模拟一级池）+ 本地 mock 一级池服务 |
| 覆盖率 | pytest-cov |
| 依赖文件 | `requirements-dev.txt`：`pytest, pytest-asyncio, pytest-cov, aioresponses` |

## 3. 测试层级

| 层级 | 说明 |
|---|---|
| 单元测试 | pool/syncer/tester/tasks 纯逻辑，网络打桩 |
| 集成测试 | mock 一级池 → 同步 → 站点测试 → 入池 → acquire 闭环 |
| 端到端 | 一级池 + 二级池 + mock 供应商跨服务联调 |
| 性能测试 | 百并发 acquire、同步吞吐 |
| 鲁棒性测试 | 一级池重启/不可达、空池、高并发竞态 |

## 7. 测试桩与 Fixture 设计

- mock 一级池：本地 FastAPI 服务，实现 `/ips`、`/ips/after/{id}`，可配置返回记录集、id 空间重置（模拟重启）、延迟/故障。
- `conftest.py`：
  - `event_loop`、`mock_session`（aioresponses）
  - `level1_client`：指向 mock 一级池的 `Level1SyncClient`
  - `pool`：预置记录（混合协议/租闲状态）的 Level2Pool fixture
  - `tester`：可注入延迟的站点测试桩
- 桩对象：一级池全量/增量/空/异常响应；站点测试 <2000ms、>2000ms、超时。

## 9. 执行方式

```bash
pip install -r requirements-dev.txt

# 单元 + 集成
pytest -v --cov=app --cov-report=term-missing

# 仅 pool（租赁核心）
pytest tests/test_pool.py -v

# 同步（空响应 max_id 判定）
pytest tests/test_syncer.py -v

# 集成
pytest tests/test_integration.py -v

# 性能
pytest tests/test_perf.py -v -m perf
```

## 10. 缺陷管理与退出准则

- **缺陷分级**：P0（阻断）必须修复复测；P1（重要）需修复；P2 可排期。
- **退出准则**：P0/P1 清零；pool/syncer/routes 覆盖率 ≥ 95%；全部用例通过后方可发布。
- 二级池改动需回归与一级池、代理层的跨项目契约（`/ips/after/{id}` 空响应 + `max_id` 语义、透传端点）。
